Code review is the most expensive place to learn a rule. In an agent-written codebase, the moment that matters is write time, and the question worth answering is “what has this team already decided about this?”

How it works

Learn the rules once, enforce them on every line

Athena builds a corpus of engineering decisions from your docs and pull-request history, then sits between your agent and your repo.

  1. STEP 1

    Onboard

    Point Athena at a repo. It reads README, CONTRIBUTING, ADRs and past PR reviews, and extracts the written and unwritten rules.

  2. STEP 2

    Recall

    Before generating code, the agent calls recall_decisions and gets the team's relevant decisions as context.

  3. STEP 3

    Check

    After writing, the agent sends its diff to check_conflict. Any violation comes back with the rule and the reasoning.

  4. STEP 4

    Record

    New decisions are saved with record_decision, and old ones are superseded with a full audit trail.

MCP tools

Six tools any agent can call

Athena speaks the Model Context Protocol over stdio or Streamable HTTP, with a matching REST API for CI, bots and the browser extension. No SDK and no agent-specific code.

ToolWhat it does
recall_decisionswrite timeSemantic search over the workspace's active decisions for this repo. Called before writing code.
check_conflictTakes a snippet or diff and returns conflicts with the violated decision and the reasoning.
record_decisionSaves a new engineering decision so future code from any agent or person respects it.
list_decisionsLists decisions, filtered by repo and status.
get_decisionFetches a single decision by id.
supersede_decisionMarks a decision superseded and links its replacement, keeping the lineage.

Self-hosting & enterprise

Runs in your VPC, on Postgres you already trust

A stateless Node server and one Postgres database with pgvector. Every decision's text and embedding live in the same row.

Air-gap ready

Use local embeddings and Ollama, and no data leaves your network. Switching providers is an environment change, not a code change.

Free to store

Decisions are never metered or capped. The corpus is your asset.

Multi-tenant

Every query is scoped to the workspace behind its API key. No query crosses workspaces.

Audited

An append-only log records every recall, check, override, supersede and delete.

Decision lifecycle

Decisions move from active to superseded to deprecated, with lineage preserved.

Scales out

HNSW index over half-precision vectors keeps search fast across millions of decisions per workspace.

Quickstart

Running locally in one command

You need Docker and an OpenAI API key.

Terminal
git clone https://github.com/AbhiRam162105/ares.git
cd ares
./setup.sh
  1. Starts the stack. Postgres with pgvector and the server on localhost:8787.
  2. Creates a workspace and prints your API key.
  3. Writes a Cursor config and can install the MCP server, skills and rule globally.
  4. Onboard a repo. Ask your agent: “Use the ares-onboard-repo skill to onboard owner/repo.”
.cursor/mcp.json
{
  "mcpServers": {
    "athena": {
      "url": "http://localhost:8787/mcp",
      "headers": { "Authorization": "Bearer <YOUR_API_KEY>" }
    }
  }
}
